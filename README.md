# Maryama — Website

Public website for **Maryama**, a three-room boutique guest house in Imsouane, Morocco.

It is a single landing page (hero, the story of the house, a photo gallery, the rooms, an FAQ and a contact footer), available in French and English. Room data comes from the Maryama API.

This folder is the website app of a small monorepo:

```
maryama/
├── api/          # Backend (serves rooms, bookings, … and the OpenAPI spec)
├── backoffice/   # Admin app
└── maryama-web/  # ← this project
```

## Tech stack

| Layer | Library |
|---|---|
| Framework | [Next.js 16](https://nextjs.org) (App Router), React 19, TypeScript 5 |
| UI | [Chakra UI 3](https://chakra-ui.com) (with Emotion) |
| Data fetching | [TanStack React Query 5](https://tanstack.com/query) + Axios |
| API client | Generated from the API's OpenAPI spec with [Orval](https://orval.dev) |
| Internationalisation | [next-intl](https://next-intl.dev): French (default) and English |
| Font | Montserrat, loaded with `next/font/google` |
| Linting | ESLint 9 with `eslint-config-next` |

## Getting started

### Prerequisites

- Node.js **20.9 or newer**
- The Maryama API running locally (see `../api`) so the rooms section has data

### Install and run

```bash
npm install
```

Create a `.env.local` file in this folder:

```bash
NEXT_PUBLIC_API_URL=http://localhost:3000   # Base URL of the Maryama API
NEXT_PUBLIC_APP_ENV=local                   # Optional: local | development | production
```

Then start the dev server:

```bash
npm run dev
```

The site runs at **http://localhost:3003**. The root redirects to `/fr` or `/en` based on the browser's language, falling back to French.

### Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | Yes | Base URL the API client calls |
| `NEXT_PUBLIC_APP_ENV` | No | Label and colour of the environment ribbon in the corner: `production` (green), `development` (red), anything else (purple) |
| `ORVAL_API_URL` | No | Where `npm run generate:api` reads the OpenAPI spec. Defaults to `http://localhost:3000/docs-json` |

## How it works

### Pages and sections

`src/app/[locale]/page.tsx` assembles the landing page from section components in `src/components/landing/`: `Navbar`, `Hero`, `ThePlace`, `PlaceGallery`, `Rooms`, `Faq` and `SiteFooter`. Each component has its own folder with an `index.tsx` (and a `props.ts` when it takes props).

Styles are written as Chakra props directly on each element. There are no separate stylesheet files per component. Shared values (colours, type scale, page width, gutters) come from `src/assets` and `src/components/landing/tokens.ts`.

### Translations

All text lives in `src/localization/locales/fr.json` and `en.json`. Components never use raw strings: they use typed keys from the generated `tKeys.ts`, so a missing or misspelt key is a TypeScript error.

To add or change text:

1. Edit **both** `fr.json` and `en.json`.
2. Run `node src/localization/generateTKeys.js`.
3. Use the key, e.g. `t(tKeys.landing.hero.title)`.

### API

The API client is generated, not handwritten. With the API running, `npm run generate:api` reads its OpenAPI spec and writes typed React Query hooks to `src/api/generated/`. A component then just calls the hook:

```tsx
const { data: rooms } = useRoomControllerFindAll();
```

All requests go through `src/utils/custom-instance.ts`, which sets the base URL from `NEXT_PUBLIC_API_URL`.
